## Decisions and trims

### Kept (per ORDER 19 §1)

- `backend/api/auth.py`, `account.py`, `setup.py` — login, forced first-login,
  password change, MFA setup completion.
- `backend/security/` — Argon2 password hashing, TOTP, recovery codes, rate
  limits, security headers, forced-flow gate.
- `backend/audit/hash_chain.py` — audit log hash chain.
- `backend/db/` — SQLAlchemy models.
- `backend/modules/pihole/adapter.py` — read-only `pihole-FTL.db` reader
  (overview card metrics).
- `backend/modules/pihole/client.py` — Pi-hole v6 REST client (status probe
  for the overview card). Management endpoints are not wired up in v0.2.
- `backend/branding.py`, `backend/config.py`, `backend/cli.py`, `backend/db/`.
- Frontend auth, account, MFA setup, force-password pages.

### Removed (ORDER 19 §1: infrastructure a normal Pi-hole user won't have)

- `backend/modules/firewall/` — nftables adapter (requires named counters in
  the `inet fortress` table; not part of a stock Pi-hole install).
- `backend/modules/ids/` — Suricata adapter (requires Suricata + its EVE log).
- `backend/modules/anomaly/` — DGA/TLD/volume anomaly engine. Depends on the
  full FTL `query_storage` table layout and is advanced analytics beyond the
  scope of this release.
- `backend/api/dns.py` — DNS lookup API hardcoded to `127.0.0.1:5335`. Pinga53
  ships its own Unbound on 5335 so this COULD stay, but it is not called out
  in §1 as "keep" and adds UI pages (Zones) we are also dropping. Can return
  later.
- `backend/api/manage.py` — Pi-hole domain/list/blocking management proxy.
  The release explicitly keeps the Pi-hole admin UI at `/admin` for these
  actions (ORDER 19 §4), so there is no reason to duplicate them inside the
  dashboard for v0.2. The REST client stays; only the mutation routes go.
- `backend/api/system.py` — querylog + anomalies routes depended on the full
  FTL query_storage schema and the anomaly engine. Audit-log reader is moved
  into a trimmed `api/system.py` (audit + status only).
- `backend/api/stream.py` — SSE stream exposed firewall+IDS composed metrics;
  pulled with those modules. Overview card polls the pihole adapter directly.
- `backend/tests/test_admin_wrapper.py` — tested a `deploy/pinga53-admin`
  shell wrapper that calls into the private repo's deployment tree (not part
  of this public release).
- Frontend pages dropped (nothing to render for them any more): `Threats`,
  `Clients`, `Devices`, `QueryLog`, `Zones`, `Blocklists`, `Settings` (settings
  is a partial page in the private source; re-introduce later).
- Frontend `hooks/useLiveFeed.ts` and the `charts/` components — they drove
  pages we removed and/or the SSE stream we removed. The Overview card now
  polls `/api/metrics` on an interval.

### Config-driven defaults

- Dashboard binds on all interfaces at **8053** (HTTPS). See `backend/config.py`.
- TLS cert/key path configurable; if unset on first start, the service
  generates a self-signed cert in `/etc/pinga53/dashboard/tls/`.
- Branding is in `backend/branding.py` and `frontend/src/brand.ts`.

## Owner questions (defaults taken)

- **Port 8053 or something else?** Took 8053 (ORDER 19 §2). Pi-hole v6 owns
  80/443 and `pihole-FTL` listens on 4711; 8053 is free and reads as "DNS via
  53, dashboard via 8053".
- **Which user runs the dashboard?** Created system user `pinga53` (not the
  existing `scamwall` user — different trust scope: `pinga53` never touches
  the engine state or the signing key; it only reads ScamWall output files).
- **Helper binary name and location?** `/usr/local/sbin/pinga53-helper`.
  Setuid-free; invoked via a sudoers drop-in for the `pinga53` user only.
- **Where does the dashboard store its DB?** `/var/lib/pinga53/dashboard.db`
  (service user owns it, systemd `ReadWritePaths` limits writes to its own
  state dir).
- **Shadow vs enforce mode detection path?** `/etc/unbound/unbound.conf.d/pinga53.conf`
  (matches `install.sh`).
- **Pi-hole app password location?** `/etc/pinga53/dashboard.env`
  (`PINGA53_PIHOLE_APP_PASSWORD`). Operator supplies at install; dashboard
  reads it at process start.
